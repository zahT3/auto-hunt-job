# 旧 DESIGN.md 评估

对象：仓库根目录的旧 `DESIGN.md`（148 行，被 git 忽略，已由 `docs/DESIGN.md` 取代），以及它对应的界面截图 `p4-frontend-orient-4f3193/tmp/` 下的 `eval-before-*`、`integrate-*`、`orient-*`。

结论：行为规则大多是对的，要原样保留；视觉和布局要推翻，原因是它们没有服务"搜索引擎 + AI 辅助"这两件核心的事，而是围绕已经冻结的工作台设计的。文档本身也要重写：一半篇幅是验收日志和 Moka 登录流程，不是设计规范。

## 保留的行为规则

这些规则跟视觉方向无关，三套原型都照做，新 DESIGN.md 原样写进去。

| 规则 | 旧文出处 | 为什么保留 |
| --- | --- | --- |
| 状态必须用文字表达，不只靠颜色 | Colors 节 "The State Text Rule" | 色弱用户、黑白打印、读屏都要能读懂；对比度不够时文字仍是兜底 |
| 未知、失败、已准备、已核验分开表达 | 同上；Layout 节"缺失证据、明确不符合、未知结果始终有文字标记" | 求职决策依赖这些区别。"没抓到"和"已经下线"混为一谈，用户会错过还在招的岗位 |
| 合成数据始终有标记 | Layout、Components 节 | 防止把演示数据当成真实岗位或真实投递 |
| 可见焦点 | Components 节最后一段 | 键盘操作是新方向的核心，焦点看不见就没法用 |
| 尊重减少动态偏好：关闭 CSS 动效和程序化平滑滚动 | 同上 | 前庭障碍用户需要；新方向 C 有分拣动效，更要有这条 |
| Escape 收起后焦点回到触发它的按钮；列表和详情更新后恢复焦点 | 同上 | 键盘用户不会在 Escape 后迷路 |
| 对外操作先审核：显示实际接收方、字段、文件、事实版本，权限分开勾选、默认不勾 | Components 节第二段 | 唯一能防止误投的环节，属于产品安全，不属于视觉 |
| 不把准备材料、点击按钮写成"已投递" | Do's and Don'ts | 同上 |
| 外部文本一律转义，链接只允许 HTTP(S) | Components 节 | 安全 |
| 原生控件优先（input、details、dialog） | Components 节 | 可访问性免费拿到，也符合"不用框架" |
| 无页面入场编排，动效只用于回应用户操作 | Components 节 | 工具界面里，入场动画只会拖慢第一眼 |

有一条要改写后保留："原生 dialog 承担受保护审核"。审核仍可以用 dialog，但定方向不再用弹窗，改成完整页面（见下）。

## 推翻的视觉和布局决定

| 旧决定 | 问题（看截图得出） | 新做法 |
| --- | --- | --- |
| 首屏是"310px 机会列表 + 详情"双栏 | 这是工作台布局。搜索结果没有分组、没有来源、没有新旧，列表只做本地过滤（旧文："不发起远程搜索"）。搜索引擎这件核心的事在首屏上没有位置 | 首屏是搜索：查询框、筛选、按岗位分组的结果、新旧状态 |
| 顶部三条横栏（品牌与运行控制、候选资料与方向、最近一轮结果） | `eval-before-desktop-1440.jpg` 里三条栏占了约 110px，全是 12px 灰字，没有主次 | 一条导航。运行状态并进搜索结果的头部，写成一句话 |
| 定方向用模态对话框 | `integrate-desktop-1440.jpg` 里对话框内部再滚动；`integrate-mobile-390.jpg` 里对话框占满屏幕，边缘露出背后页面，四个方向挤成一列小字 | 做成完整页面，有自己的地址，可以回来继续 |
| 匹配依据是一张平铺表：地点、年限、薪资、具体要求混在一起，每行一个米色标签 | 截图里 6 行全是同样的米色小标签，看不出哪条是硬门槛 | 按招聘方 ATS 的顺序分三段：硬条件 → 关键词覆盖 → 事实证据 |
| 配色：浅灰绿画布 `#f7f8f6`、墨绿强调 `#38634d`、米色警示底 | 低饱和的灰绿加米色，是 Notion 式模板的默认感觉，用户说的"AI 味"主要来自这里；状态全是米色或浅红小块，彼此区分度很低 | 每个原型重新定色，状态用"形状 + 文字"区分，不靠一排同色小块 |
| 正文 14px、辅助 12px，整体偏小 | 截图里大量 12px 灰字，1440 宽的屏幕右侧一半是空的 | 正文 14–16px，长段中文 16–17px，按少数派实测的 1.8 行高 |
| 品牌写成英文 slug "auto-hunt-job" | 中文界面里显得像没起名字 | 原型里用中文名占位，最终名字由用户定 |
| "Creative North Star""Key Characteristics"这类小标题 | 生成器模板的痕迹，没有信息 | 新文档按"原则 → 令牌 → 页面 → 组件 → 行为规则"组织 |

## 文档结构的问题

- 一半篇幅不是设计规范：1440×1000 验收记录、23 项合同测试、截图路径、Moka 登录核验的流程。这些属于测试报告和后端说明，放进设计文档会过期，也会让设计规则被淹没。
- 断点写得过细（"701–1100px 宽度暂收起列表"），却没写为什么。新文档每个布局决定后面跟原因。
- 简历工作室的蛛网动效占了一整节。它是可选特效，新文档只留一段"例外动效"的说明和边界。
