# 找全程度基准（AI 产品经理）

这个基准回答一个问题：在"AI 产品经理"这个方向上，真实在招的岗位，工具一轮搜索能找回几成。

## 标准答案怎么来

标准答案文件不入库，存放在 `private/benchmark/ai-pm/truth-YYYY-MM-DD.json`，格式见 `hunt/benchmark.py` 的 `load_truth`。整理方法：

1. **选公司**：选约 30 家确定在招 AI 产品经理的公司，包括大厂、大模型公司和 AI 应用公司。工具现在读不了的公司也要放进来，否则数字只反映"能读的公司里漏了多少"，看不出哪些公司根本没接入。
2. **列岗位**：每家都从官方招聘来源取一份产品岗清单，取法从上到下优先：
   - 种子能读的，用程序宽搜「产品经理」或「产品」。宽搜词比工具实际用的方向词更宽，所以标准答案不是"工具自己验证自己"。
   - 种子 URL 不对、但官网指向 Moka/飞书页面的，用程序读真实页面。
   - 其余的在浏览器里人工读官网列表。
   大公司宽搜结果上千条的，只取前 200 条，并在文件里标为截断。
3. **逐条核对**：判定规则写在文件的 `rule` 字段里，大意如下：
   - 标题是产品岗，并且写明了 AI 方向，才算。
   - 纯大模型公司的产品岗全部算。
   - 只写「智能」的不算；工程师、设计师、分析师、纯运营不算。
   边界标题逐条人工判，结果记在判定脚本里。
4. **读不了的公司**：记进 `excluded` 字段并写明原因，不计入分母。原因包括：
   - 官网拒绝访问、空白或 404；
   - 标题全是「产品经理（编号）」，无法按标题判断方向。

## 跑一次

```bash
python -m hunt benchmark --truth private/benchmark/ai-pm/truth-2026-10-27.json --data private/benchmark/ai-pm/data
```

`--data` 指向跑过一轮搜索的数据目录。`--direction ai-product-manager` 只比对归到这个方向的岗位；不加时比对全部岗位。报告默认写到标准答案同目录的 `report-日期.json`。

## 平台采样（BOSS、猎聘，需要你本人操作）

平台岗位需要登录才能看，工具不会自动登录，所以"含平台"这一栏要靠你用书签采样：

1. 在工作台点"岗位书签"，或打开 `/bookmarklets`，安装书签。
2. 在 BOSS 或猎聘搜「AI 产品经理」，每个城市翻前 3 页；每页点一次书签，把当前页发到本机收件箱。
3. 采完后，把收件箱里的岗位与标准答案按公司和标题比对，计入"含平台"一栏。

书签只发送你点击那一刻看到的页面，不会自动翻页，也不会登录或投递。

## 局限

- 标题判定会漏掉标题里不写方向的 AI 岗位，这在百度最明显。也会把部门名带 AI 的普通产品岗算进去。
- 大公司只核对了宽搜的前 200 条，召回率只能说明"这 200 条里找回了多少"。
- 标准答案是某一天的快照。岗位每天都在变，隔几天再比，会把新开或已关的岗位算成差异。
