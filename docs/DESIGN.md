# auto-hunt-job 界面设计规范

本文规定 auto-hunt-job 网页界面的设计方向、令牌、组件、页面布局和必须遵守的行为规则。对照实现可以看 `prototypes/final/`（合成数据的静态原型，结构和后端接口一致）。参考研究在 `research/references.md`，细节工艺的出处在 `research/craft-details.md`，对旧规范的评估在 `research/old-design-review.md`。

## 1. 方向

**整体用"荧光笔"：白纸黑字的检索台，键盘优先。岗位详情用"批注"：JD 原文按段读，旁边是页边批注。**

理由：

- 产品的核心是两件高频的事：在很多条岗位里找、分、比；读一份 JD 时看清自己哪里够、哪里不够。高频操作要快，所以整体界面少装饰、全程能用键盘做完，键盘触发的动作不播动画（Emil Kowalski、Rauno Freiberg 的观点，见 `research/craft-details.md` 第 7 条）。
- 读 JD 是低频、需要专注的事，所以详情页换成阅读节奏：原文用宋体，顾问的批注放在页边、用楷体和蓝色，判断用批改符号。
- 两部分共用一套令牌：同样的灰阶、同样的状态色、同样的荧光笔黄和间距。区别只在详情页的正文字体和页边批注。

几条贯穿全局的原则：

1. 颜色只表达三种意思，各有专用色。荧光笔黄 = 关键词覆盖（简历有 JD 原词）；圆珠笔蓝 = AI 或顾问说的话；绿、琥珀、红 = 状态。别的地方都是黑白灰。
2. 状态永远是"形状 + 文字"，颜色只是第三层提示。
3. 只说本机知道的事。岗位库只有 `first_seen`、`last_seen`、`status`，界面就说"首次搜到""最近搜到""仍在列表"，不说"发布""在招"。
4. 每个判断都能追到依据：事实编号（f1…）、JD 原文片段、来源记录。
5. 空状态、失败、未知都要写清是什么、为什么、下一步做什么。

### 字体

| 令牌 | 字体栈 | 用在哪里 |
| --- | --- | --- |
| `--ui` | 打包的 Inter → 打包的思源黑体子集 → 系统无衬线 | 固定界面文字：导航、按钮、标题、标签、表头、状态词 |
| `--text` | 打包的 Inter → 系统无衬线 | 动态内容：岗位名、公司、薪资、事实原文 |
| `--serif` | Songti SC → STSong → Noto Serif SC → Source Han Serif SC → 系统无衬线 | 只用于岗位详情的 JD 原文、预览里的 JD 摘录、结构化结果的原文依据 |
| `--hand` | Kaiti SC → STKaiti → KaiTi → LXGW WenKai → 系统无衬线 | 只用于页边批注、匹配分数、批改符号 |

系统无衬线是 `-apple-system, BlinkMacSystemFont, "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", "Noto Sans SC", sans-serif`。

字号：12（键帽、表头）、13（辅助、元信息）、14（正文、界面）、15（列表标题、查询框）、16（区块标题、批注）、17（JD 原文）、22（预览标题）、24（页面标题；手机 21）。行高：界面 1.6，JD 原文 1.9，批注 1.6。JD 原文每行不超过 40 个汉字（`--measure: 40em`）。

全局排版设置：`font-variant-numeric: tabular-nums`（等宽数字）；`text-autospace: normal`（来源抓来的"AI后台开发"这类文本自动补中西文间距）；`text-spacing-trim: normal`（挤压相邻标点）；`line-break: strict`（行首行尾禁则）。自己写的文案在中西文、数字和单位之间手动加空格。

### 间距、圆角、阴影

- 间距按 4 的倍数：4、8、12、16、24、32、48（`--s1`…`--s7`）。
- 圆角：标签 2px，控件 4px，面板和弹层 6px，命令面板 8px。
- 阴影只给浮层（筛选菜单、命令面板）。深色模式下浮层用 1px 描边加深色阴影。普通内容不加阴影，用分隔线分组。

### 动效

| 用途 | 时长 | 缓动 |
| --- | --- | --- |
| 颜色、边框变化 | 160ms | ease-out |
| 按钮按下缩到 0.97 | 120ms | ease-out |
| toast 出现 | 透明度 160ms，位移 200ms | ease-out |
| 提示框出现（从 0.97 缩放） | 120ms | ease-out |

- 界面动画不超过 300ms；只写具体属性，不写 `transition: all`。
- 键盘触发的动作（J/K、1/2/3、U、⌘K）不播动画，列表直接变。
- 没有页面入场动画，没有滚动驱动的动画。
- `prefers-reduced-motion: reduce` 下关掉全部过渡、动画和程序化平滑滚动。

### 深色模式

跟随系统 `prefers-color-scheme`，同时设 `color-scheme: dark`，让滚动条和原生控件一起变深。

- 不用纯黑纯白：底色 `#17181a`，正文 `#e2e4e7`（Material Design 的深色建议是深灰底、约 87% 的白字）。
- 浅字在深色底上看起来更粗（光渗错觉）。业界做法是用可变字体的 GRAD 轴调细（Adam Argyle），或者把字重乘一个系数（CSS-Tricks）。我们打包的字体没有 GRAD 轴，所以用字重系数：全局 `font-variation-settings: "wght" calc(var(--fw) * var(--wm))`，深色 `--wm: 0.9`。要设粗细的元素同时设 `--fw`。
- 系统中文字体（苹方、宋体、楷体）不是可变字体，系数对它们无效。把 400 写成 360 又会匹配到 300 Light，太细。所以系统字体正文保持 400，粗体从 600 降到 500（`--strong`）。
- 荧光笔黄在深色下稍暗（`#e9cf47`），黄底上的字仍是深色。

## 3. 字体打包

| 文件 | 来源 | 内容 | 大小 |
| --- | --- | --- | --- |
| `inter.woff2` | Inter，google/fonts `ofl/inter/Inter[opsz,wght].ttf` | 基本拉丁、拉丁补充、常用标点和符号；wght 300–700，保留 opsz | 56 KB |
| `sans-ui.woff2`（原型里叫 `sans-final.woff2`） | Noto Sans SC，`ofl/notosanssc/NotoSansSC[wght].ttf` | 界面代码里出现的约 500 个汉字和 ASCII；wght 400–700 | 108 KB |

合计 164 KB，预算 1.5 MB。

规则：

- 只用 SIL OFL 或同等宽松许可的字体。文件放 `static/fonts/`，许可证原文（`OFL-*.txt`）放在一起，署名写进 `THIRD_PARTY_NOTICES.md`。运行时从本机加载，不连外网。
- 中文字体只给固定的界面文字用。JD 原文、公司名这些动态内容用字不可预知，继续用系统字体。界面字体里缺字时，浏览器逐字回退到系统字体，不会出现豆腐块。
- 子集用 `prototypes/_tools/subset_fonts.py` 生成（fontTools）：扫描界面代码里的汉字，加上 ASCII，保留 `kern`、`tnum`、`halt`、`palt` 等特性。改了界面文字要重新生成，否则新字会回退到系统字体。`prototypes/_tools/build_fonts.sh` 是一键脚本，源字体不进仓库。
- `font-display: swap`。字体没加载完时文字用系统字体显示，不留空白。首屏要用的 Inter 加 `<link rel="preload">`。
- Noto Sans SC 的许可保留了字体名 "Source"。子集是修改版，文件名和 CSS 字体族名（"AH Sans" 一类）都不能用 "Source"。

### Windows 回退

宋体、楷体只有 macOS 自带。Windows 上的回退是一个明确的决定，不靠运气：

- JD 原文（`--serif`）：依次找 Noto Serif SC、Source Han Serif SC（用户自己装过的），都没有就回退到系统无衬线（Windows 上是微软雅黑）。**故意不回退到 SimSun。** SimSun 在 Windows 上正文字号下的效果我们没有实际看过，宁可回到无衬线，保证读得清。以后在 Windows 上实测后，可以把 SimSun 加进来。
- 页边批注（`--hand`）：依次找 Kaiti SC、STKaiti、KaiTi（Windows 中文版通常有，但没验证）、LXGW WenKai，都没有就是系统无衬线。批注不靠楷体被认出来：它有自己的颜色（圆珠笔蓝）、左边线和位置（页边）。换成无衬线以后，仍然能一眼看出这是批注。
- 地址加 `?fonts=windows` 可以在 Mac 上模拟这条回退链（去掉只有 macOS 才有的字体）。加 `?fonts=system` 可以看不用打包字体时的样子。

## 4. 状态语言

### 岗位新旧（来自 `/api/search` 的 `first_seen`、`last_seen`、`status`）

时间是 UTC，按北京时间算"今天""N 天前"。一周内写相对时间，更早写日期（"9 月 18 日"）。

| 条件 | 状态词（形状） | 说明句 |
| --- | --- | --- |
| `status=open`，首次搜到在 2 天内 | 新搜到（实心绿点） | "2 天前首次搜到，今天还搜得到" |
| `status=open`，最近 3 天内搜到过 | 仍在列表（实心绿点） | "9 月 18 日首次搜到，今天还搜得到" |
| `status=open`，最近一次搜到在 3 天以前 | 近几天没搜到（半实心琥珀点） | "6 天前首次搜到，3 天前最近一次搜到" |
| `status=closed` | 已不在列表（灰色 ✕） | "最近一次搜到是 10 月 17 日，之后连续两轮没再出现" |

- 搜索页的说明行写明："只查本机岗位库；'在列表'是本机库的判断，不等于招聘方仍在招。"（对应接口的 `note`）
- **不写"发布""新发布""在招"。** 只有来源自己给了发布日期时才显示，并写明是哪个来源说的："Greenhouse 写的发布日期：10 月 27 日"。现在的接口没有这个字段；原型里用 `sources[].posted_at` 预留，后端加上后按这个写法显示。
- 来源记录逐条显示 `status`：在列表 / 已不在列表。某个来源这一轮失败或结果被截断，设置页要写出原因，并说明"那一轮不会把没取到的岗位标成已不在列表"。

### 匹配解释（来自 `job_match`）

按招聘系统的顺序分三步，每一行都用批改符号加文字：

| 段 | 字段 | 符号和文字 |
| --- | --- | --- |
| 第 1 步 硬条件 | `hard[].status` | `met` → ✓ 符合；`not_met` → ✗ 不符合；`unknown` → ？ 不知道 |
| 第 2 步 关键词覆盖 | `keywords[].coverage` | `explicit` → 黄底，有原词；`related` → 琥珀虚线框，～ 相近说法；`absent` → 红色删除线，没有 |
| 第 3 步 事实证据 | `evidence[]` | 有 `fact_ids` → ✓ 有事实；只有 `related_fact_ids` → ～ 只有相近事实；都没有 → ✗ 没有事实 |

- 不打分、不排序，不预测筛选结果。每段的"3 / 5"只是条数，写在段首。
- "不知道"和"不符合"永远分开。例如英语六级的事实存在但还没确认，就是"不知道"，并写明原因。
- 只引用已确认的事实。还没确认的事实在页头点名（"f7、f8 还没确认，没有拿来对照"），并给出去确认的入口。

### 其他

- 事实编号用小标签显示（`f3`），虚线边框表示还没确认。悬停或聚焦显示原文和出处。
- AI 生成的内容标"AI 建议""AI 追问"，用圆珠笔蓝；本地规则生成的标"本地规则"。
- 合成数据在顶栏常驻"合成数据"标记。

## 5. 组件

| 组件 | 规则 |
| --- | --- |
| 顶栏 | 52px，吸顶。左：产品名 + 合成数据标记；中：导航（搜索、分拣 N、定方向、设置）；右：上一轮运行状态一句话（截断时 `title` 给全文）+ "开始搜索"主按钮 |
| 查询框 | 一个输入框，右侧键帽"/"。下面一排筛选下拉：城市、方向、来源、搜到时间。城市和方向是单选，跟接口一致 |
| 条件回显句 | 把当前条件写成一句话："在 上海 找 后端开发，看 全部来源，只看最近 7 天搜到过、仍在列表的：11 条记录合并成 7 组。" 被时间条件挡住的组要说出数量，并给"一起显示" |
| 结果组 | 一组 = 同公司、同标题、同城市的记录。显示：标题、薪资（取第一个写了薪资的来源）、公司和城市和方向、新旧状态词 + 说明句、卡片选择标签、来源行（折叠，展开是键值表：来源 / 状态 / 首次搜到 / 最近搜到 / 说明）。已不在列表的组标题变灰 |
| 预览 | 桌面在右栏显示当前组：标题、新旧、JD 摘录（宋体，标明来自哪个来源）、匹配解释三步的条数、"打开详情 ↵"。手机不显示预览，点开就是详情 |
| 底部操作条 | 52px，固定在底部，只在搜索（桌面）、详情、分拣出现。左：当前岗位；右：感兴趣 1 / 稍后 2 / 跳过 3 / 全部操作 ⌘K。当前选择用黄底表示 |
| 命令面板 | ⌘K 打开原生 `<dialog>`，每个动作右边写它的快捷键。关闭后焦点回到打开前的位置 |
| 提示框 | `data-tip`。第一次悬停等 400ms 再出现；刚关掉一个、600ms 内指向下一个，立即出现且不播动画；移开立即消失；键盘聚焦也会出现，Esc 关掉 |
| toast | 底部居中，`aria-live="polite"`，5 秒后消失。分拣后带"撤销（U）" |
| 骨架 | 工作超过 150ms 才出现，出现后至少停 400ms。行高和真实结果行一致（实测 131px）。按钮文字改为"正在搜索…"并禁用，容器加 `aria-busy` |
| 空状态 | 写清搜了什么、为什么空，给一个放宽条件的按钮（"放宽到 30 天"）。分拣某组为空时说明怎么把岗位放进来 |
| 状态词 | `.st`：形状 + 文字。实心点 = 好，半实心 = 注意，✕ = 不在 / 失败，空心圈 = 未运行。不做成按钮的样子 |
| 批改符号 | `.mark`：✓ ✗ ？ ～，用楷体字形，配文字 |
| 页边批注 | 楷体、圆珠笔蓝、左边 2px 浅蓝线。依据的事实编号用界面字体写在下一行 |
| 证据高亮 | JD 原文里：关键词按覆盖程度用荧光笔（黄底 / 琥珀虚线 / 红波浪线）；硬条件和证据用下划线（绿实线 = 有，灰点线 = 不知道，红波浪线 = 没有）。"定位原文"会给对应片段加黑框并滚过去 |
| 表单 | 原生控件。标签和控件在同一个 `<label>` 里。密钥框只显示"已保存，尾号 3f9c" |
| 发送同意 | 四个类别逐个勾选，默认都不勾；"完整简历"的说明用红字。下面写明这份同意绑定的服务地址和模型 |

点击区域：桌面上可点元素至少 24px（按钮 32px，筛选标签 28px，事实编号 24px）；手机上按钮和带复选框的标签至少 44px。

## 6. 页面布局

### 搜索（首页）

- 桌面：左栏 600px（查询框、筛选、回显句、结果列表，自己滚动），右栏是预览，底部是操作条。
- 手机：单栏。顶栏两行（第二行是导航），查询框下筛选换行，结果列表在下面；不显示预览和底部操作条，点岗位进详情。
- 排序跟接口一致：仍在列表的在前，标题含全部检索词的在前，再按最近一次搜到的时间。

### 岗位详情

- 最大宽度 1240px，居中。
- 页头左：返回链接（Esc）、标题、公司和地点和薪资、新旧状态、来源给的发布日期（有才显示）。页头右（页边位置）：一条批注，写明用了几条已确认事实、哪些还没确认。
- 下面是匹配解释的三栏，并排，从左到右是第 1 步硬条件、第 2 步关键词覆盖、第 3 步事实证据。每栏顶部写这一步的意思（"招聘系统先按这些筛人""再看简历里有没有原词""最后才有人读"）和条数。
- "原文与批注"：左栏是 JD 原文（宋体 17px，每段编号，最多 40 字一行），右栏页边对着每段放批注。
- 然后是"结构化结果"（定义列表，每项后面用宋体写原文依据）和"来源记录"表。
- 手机：三栏变成上下三段；批注排到它对应那一段的下面。

### 分拣

- 顶部分组标签：待选 / 感兴趣 / 稍后 / 跳过，带总数（不是未读数）。Tab / Shift+Tab 在分组间切换。
- 下面是当前分组的列表；选中的一行展开，显示说明句和动作按钮。1/2/3 分拣、U 撤销，选中下一行。
- 页头说明：选"感兴趣"后会开始准备材料，材料要审核后才会用。

### 定方向

- 完整页面，不用弹窗。桌面两栏（左 5 : 右 7）。
- 左栏：你的回答（定义列表，每行有"改"）、由回答得出的搜索条件、追问（还没回答的问题，单选选项，AI 追问有标签）。
- 右栏：建议方向对比表，列是方向，行是理由 / 优势 / 短板 / 风险 / 搜索词。每条优势、短板、风险后面跟事实编号和"JD N 处"（悬停看原文）。搜索词里不在合并 8 词里的标"本轮不搜"。下面是"采用这 N 个方向"和"修改方向"。
- 下面通栏：暂不建议优先投（`not_recommended`，带理由和依据）、今天就能做（`next_actions`，每条一个按钮：开始找岗位 / 去回答 / 补充事实 / 去确认 / 看匹配解释）。
- 手机：单栏；对比表按方向竖排。

### 设置

- 左侧分区导航（AI 服务 / 发送同意 / 来源），右侧内容。
- AI 服务：服务地址、模型、密钥（只显示尾号）、本月花费和上限的计量条。
- 发送同意：四个类别，绑定的服务地址和模型、授予日期。
- 来源：表格，列是启用 / 来源 / 上次运行（状态词 + 原因）/ 岗位数。状态包括成功、失败、需要登录、结果被截断、还没运行。

## 8. 必须遵守的行为规则

以下规则从旧规范保留，和视觉方向无关：

- 状态必须用文字表达，不只靠颜色。
- 未知、失败、已准备、已核验分开表达；"不知道"不等于"不符合"，"没抓到"不等于"已下线"。
- 合成数据始终有可见标记。
- 键盘焦点始终可见：只用 `:focus-visible`，2px 实线、2px 偏移；吸顶栏和底栏不能挡住被聚焦的元素（`scroll-padding`）。
- 尊重减少动态偏好：关闭 CSS 动效和程序化平滑滚动。
- Escape 收起后焦点回到触发它的元素；列表和详情更新后恢复焦点；路由切换后焦点移到新页面的标题。
- 对外操作先审核：审核同时显示公开岗位来源和实际申请接收方；字段、最终文件、事实版本、披露范围都要具体呈现；填写、上传、提交权限分别勾选，默认不勾；必填缺失或硬条件不符不能批准。审核仍可用原生 `<dialog>`。
- 不把准备材料、点击按钮写成"已投递"。
- 外部文本一律转义；链接只允许 HTTP(S)；导航用 `<a>`。
- 原生控件优先（input、details、dialog）。
- 无页面入场编排；动效只用来回应用户操作。
- 运行时不加载外部资源；CSP 为 `script-src 'self'`。

## 9. 细节清单落实情况

逐条的出处和做法见 `research/craft-details.md`。在这套规范里的落点：

| 类别 | 落实 |
| --- | --- |
| 深色字重和颜色 | 第 2 节"深色模式" |
| 等宽数字 | 全局 `tabular-nums` |
| 中英间距、标点挤压 | 全局 `text-autospace`、`text-spacing-trim`、`line-break: strict`，文案手动加空格 |
| 焦点环 | 第 8 节 |
| 点击区域 | 第 5 节末 |
| 悬停意图延迟 | 提示框组件 |
| 缓动和时长 | 第 2 节"动效" |
| 加载不跳动、骨架 | 骨架组件。已知缺口：打包字体换入时拉丁文字宽会微变，还没用 `size-adjust` 处理 |
| 空状态 | 空状态组件 |
| 长文本截断加提示 | 只在顶栏运行状态、底栏当前岗位处截断，都带 `title`；正文和岗位名换行，不截断 |
| 选中文字颜色 | `::selection` 用荧光笔黄 |
| 滚动条 gutter | `html` 和两栏滚动区都设 `scrollbar-gutter: stable` |
| 减少动态 | 第 2 节"动效"、第 8 节 |
